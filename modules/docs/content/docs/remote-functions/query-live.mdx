---
title: Query.live
description: Stream remote query values with Effect Streams.
---

Use `Query.live` when the server should keep sending values while the client is still interested in them. The server handler returns an Effect `Stream.Stream`, and the client call returns a `RemoteLiveStream`: an Effect Stream with transport metadata for `Live`.

## When to use this

Use `Query.live` for clocks, presence, notification counts, job progress, or event feeds. Use `Query` when the value is a snapshot the user can refresh explicitly.

## Minimal working example

```ts
import { Query } from "svelte-effect-runtime/server";
import { Schema, Stream } from "effect";

export const get_clock = Query.live(Schema.String, (_clock_id) =>
	Stream.tick("1 second").pipe(Stream.map(() => new Date().toISOString())),
);
```

```svelte
<script lang="ts" effect>
	import { Effect, Stream } from "effect";
	import { Live } from "svelte-effect-runtime";
	import { get_clock } from "./clock.remote";

	let time = $state("Connecting...");

	const clock = get_clock("main");

	yield* clock.pipe(
		Stream.runForEach((next) =>
			Effect.sync(() => {
				time = next;
			}),
		),
	);
</script>

<p>{time}</p>
<button onclick={yield* clock.pipe(Live.reconnect)}>Reconnect</button>
```

## Stream sources

`Query.live` handlers return Effect Streams:

```ts
import { Query } from "svelte-effect-runtime/server";
import { Stream } from "effect";

export const watch_jobs = Query.live(() =>
	Stream.tick("1 second").pipe(Stream.map(() => ({ checked_at: Date.now() }))),
);
```

Native iterables are not accepted directly. Wrap them before returning:

```ts
import { Query } from "svelte-effect-runtime/server";
import { Stream } from "effect";

async function* make_counter() {
	let count = 0;

	while (count < 3) {
		yield count;
		count += 1;
	}
}

export const watch_counter = Query.live(() =>
	Stream.fromAsyncIterable(make_counter(), (error) => error),
);
```

## Client shape

Calling a live query returns a `RemoteLiveStream`. It behaves like an Effect Stream:

```ts
import type { RemoteLiveStream } from "svelte-effect-runtime";

const clock = get_clock("main");
const typed_clock: RemoteLiveStream<string> = clock;

const labels = clock.pipe(Stream.map((time) => `Updated at ${time}`));
```

In SER markup and `<script effect>`, `yield* clock` resolves the first emitted value. To keep state updated as values arrive, consume the stream with `Stream.runForEach`.

Transport state is separate from the data stream:

```ts
const status = clock.pipe(Live.status);
```

`clock.pipe(Live.status)` is also a stream. Consume it the same way as the live query when the UI needs to show connection state.

Manual reconnect is an Effect:

```svelte
<button onclick={yield* clock.pipe(Live.reconnect)}>Reconnect</button>
```

Automatic reconnect is ordinary Effect composition. Put the retry policy on the stream you consume:

```ts
import { Schedule, Stream } from "effect";

const resilient_clock = clock.pipe(
	Stream.retry(Schedule.exponential("100 millis").pipe(Schedule.take(5))),
);
```

## Migrating from live resources

Old live query resources mixed data, connection state, and transport methods on one object. `Query.live` now separates those concerns.

For values, keep local component state and update it from the stream:

```svelte
<script lang="ts" effect>
	import { Effect, Stream } from "effect";
	import { get_clock } from "./clock.remote";

	let time = $state<string | undefined>();
	const clock = get_clock("main");

	yield* clock.pipe(
		Stream.runForEach((next) =>
			Effect.sync(() => {
				time = next;
			}),
		),
	);
</script>
```

For transport state, use `clock.pipe(Live.status)` instead of `clock.ready`, `clock.loading`, `clock.connected`, or `clock.done`.

For manual reconnects, use `yield* clock.pipe(Live.reconnect)` instead of `clock.reconnect()`.

For async generators or native iterables, wrap the source in a Stream before returning it from the server handler.

## Common mistakes

- Using live queries for data that only changes after a user action.
- Forgetting that every active live query keeps server work alive.
- Returning a `Promise`, async generator, or native iterable from `Query.live`. Return a `Stream`.
- Reading `clock.current`, `clock.ready`, or `clock.connected`. Use stream state in your component, and use `clock.pipe(Live.status)` for transport state.
- Calling `clock.pipe(Live.reconnect)` without yielding or running the returned Effect.
