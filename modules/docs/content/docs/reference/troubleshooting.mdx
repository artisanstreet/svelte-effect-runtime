---
title: Troubleshooting
description: Fix common setup, transform, and remote function problems.
---

Most issues come from plugin order, missing remote function configuration, or using server code from the browser.

## The effect script is not transformed

Check the script tag and plugin order:

```svelte
<script lang="ts" effect>
  import { Effect } from "effect";
</script>
```

```ts
plugins: [effect(), sveltekit()];
```

If another Vite plugin parses Svelte component files, make sure `effect()` runs
first:

```ts
plugins: [effect(), otherParserPlugin(), sveltekit()];
```

## Possible Vite Plugin Ordering Conflicts

SER lowers `<script effect>` and `yield*` before normal Svelte parsing. Some
Vite plugins run early and may inspect component files before SER has lowered
its syntax.

When SER notices that setup, it prints a non-fatal info message:

```txt
Svelte Effect Runtime noticed possible Vite plugin ordering conflicts.

These plugins run before normal Svelte component transforms:
  - example-plugin

This is usually fine, but if you see Svelte parser errors around <script effect>
or yield* in components, one of those plugins may be reading component files before
SER has lowered its syntax.
```

If the app works, you can ignore the note. If Svelte reports parser errors
around SER syntax, check whether one of the listed plugins is parsing component
source before SER runs.

## Remote functions do not resolve

Enable SvelteKit remote functions:

```js
const config = {
	kit: {
		experimental: {
			remoteFunctions: true,
		},
	},
};
```

## A browser build imports server code

Move database clients, secrets, cookies, and request-only services into remote handlers or server runtime layers.

## Code examples render strangely

Use plain fenced code blocks and Fumadocs JSX components. Avoid legacy directive fences.
